# 自走改善の憲章

ユーザーの指示が無くても、リアルカードバトルの品質を上げ続けるための取り決め。次の実行はここから読み始める。

## プロダクトゴール（2026-10-24 ユーザー指示）

**ドラクエライバルズとクラッシュ・ロワイヤルを掛け合わせた、新感覚のリアルタイムカードゲーム。**
画面 UI・音源・演出の質は、この 2 作に劣らないこと。戦略とプレイヤースキル（PS）が要り、中毒性があること。
騙す・煽る・不利益を隠す設計（ダークパターン）は使わない。

### 進め方（スクラム。ユーザーの指示待ちにしない）

- 1 周 = 1 スプリントの一区切り。バックログのリファインメント（調べて・割って・並べ替え）→ 実施 → 検証 → 公開 → ふりかえり（journal）。
- 指示を取り入れるだけでなく、**プロダクトゴールに照らして自分で課題を見つけ、バックログへ積む**。
  ネタ元: クラロワ／ライバルズとの差（画面・手触り・成長・対戦の深み）、CPU 同士の測定、実機での確認、ユーザーの感想。
- 優先度の目安: ①対戦の面白さ（戦略・PS・読み合い） ②手触り・演出・音 ③成長・中毒性 ④画面の質。バグは最優先。
- ユーザーにしか決められないもの（外部サービス・素材の生成のダウンロード・課金・オンライン対戦のサーバー）は、
  設計案とともに質問を溜め、周の終わりにまとめて聞く。

## 守る核

`src/game/` のゲーム性（クールタイム制の攻撃・割り込み・上書き・予約）。壊さない。

## 許可

- 変更してよい範囲: UI・演出・操作性・カードバランス・CPU。ルールの根幹は変えない。
- 公開: `npm run deploy` を修正のたびに。
- 条件: 変更前に `git tag autopilot/<連番>-<名前>`。ルール数値を変えたら `npm run simulate` / `npm run audit` で前後を測り journal に書く。
- 相談が要るもの: 課金、外部サービスへの送信、音の差し替え（音は録音のみ）。

## 並列と分担

- 既定 sonnet、並列は 2 件まで。コードを書かせるときは `isolation: worktree`。
- ブラウザは URL に `?mute`。playwright は待ちに必ず timeout。

## 測定の道具

| 目的 | コマンド |
|---|---|
| テスト | `npm test` / `npm run typecheck` |
| 勝率・試合時間 | `npm run simulate` |
| カード別勝率 | `npm run audit` |

## 止める条件

- 同じ領域で 3 回続けて改善なし → その領域を止める。
- 公開版が壊れたら最優先でタグへ戻す。

## レビューの入口（感想箱）
